# 出单统计日报 → 飞书多维表格

每天把出单统计表（16 列的日报）同步进飞书多维表格。唯一键 `统计周期 + 用户ID`，
同一份文件重复跑只会更新、不会写重。

跟 `workwork` 仓库里的 `出单监控.py` **不是一回事**：那个读的是「商户审核耗时报表」
（sheet2、字段是 `累计TPV_USD / 第一笔成功交易时间` 那套），做的是出单状态分类打标。
本脚本只做原样入库，两者列名无一重合，各用各的多维表格。

---

## 安装

```bash
pip install -r requirements.txt
```

`.xls` 必须用 `xlrd` 读 —— WPS 导出的是 OLE2 格式，LibreOffice 直接报
`source file could not be loaded`。

## 配置

飞书开放平台建自建应用，权限勾 `bitable:app:readonly` + `bitable:app`，
**再把应用加为目标多维表格的协作者**（漏了这步读字段就 403）。

凭据两种给法，环境变量优先：

```bash
export FEISHU_APP_ID=cli_xxx
export FEISHU_APP_SECRET=xxx
export BITABLE_APP_TOKEN=xxx      # URL 里 /base/ 后面那段
export BITABLE_TABLE_ID=tblxxx    # URL 里 ?table= 后面那段
```

或者 `cp config.example.json config.json` 填进去（`config.json` 已 gitignore）。

## 跑

```bash
python sync.py --file 出单统计.xls              # 同步
python sync.py --file 出单统计.xls --dry-run    # 只解析打印，不写飞书，不需要凭据
python sync.py --dir D:\报表                    # 取目录里修改时间最新的 xls/xlsx
python sync.py --file x.xls --date 2026-08-06   # 文件含多天时只同步指定那天
```

先跑一次 `--dry-run` 确认解析对，再去掉参数真同步。

## 多维表格字段

字段名要和报表列名**一字不差**，对不上的列脚本会打印出来并跳过（不会报错）。
`统计周期` 和 `用户ID` 是唯一键，这两个缺一个脚本直接中止。

| 报表列 | 建议字段类型 | 说明 |
|---|---|---|
| 报表类型 / 账户等级 / 商户名称 / 直签人 / 代理商名称 / 站点 / 接入模式 | 文本 | 单选也行，脚本会按类型转 |
| 统计周期 | 文本 或 日期 | 两种都支持，脚本读表结构自动适配 |
| 用户ID / 代理商用户ID | **文本** | 19 位，设成数字会精度丢失 |
| 交易金额（美元）/ 环比增长金额（美元）/ 交易笔数 / 环比增长笔数 | 数字 | |
| 金额环比 / 笔数环比 | 数字（百分比格式） | 报表里是小数，`-0.0884` = `-8.84%`，脚本原样写，格式在多维表格里设 |

## 几个坑

**用户ID 必须导出成文本。** 19 位超过 float64 的 53 位有效精度，一旦导出成数字格式，
`1828351428978479107` 读出来是 `1828351428978479104` —— 末几位在到达脚本之前就没了，
救不回来。脚本检测到会**直接中止**而不是写错数据进去，因为错 ID 既污染表、又跟历史记录对不上。
报错了就去导出端把该列改成文本。

**环比是小数不是百分数。** 报表里 `0.0178` 表示 1.78%。多维表格字段设成数字+百分比格式即可，
别在脚本里乘 100，否则跟报表对不上。

**表头不一定在第一行。** 脚本会在前 10 行里找包含「报表类型/统计周期/用户ID」的那行当表头，
标题行、空行都能跳过。合计行（没有用户ID）不入库。

**读已有记录走的是按统计周期检索**，不是全量扫表 —— 表一天天涨，全量拉迟早慢到不可用。
检索接口不可用时会自动回退全量并打印提示。
